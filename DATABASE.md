# DATABASE.md — Foundry

> PostgreSQL 15 + pgvector. Schema lives in `packages/db/src/schema.ts` (single file, Drizzle). This document is the human-readable contract; the schema file is the machine truth. Change the schema → regenerate migration → update this doc in the same PR.

---

## 1. Conventions

- Table names: `snake_case`, plural (`posts`, `room_members`).
- PKs: `id` UUID, `gen_random_uuid()` default.
- Timestamps: `created_at` (default now) on everything; `updated_at` only where rows mutate (posts, rooms, rubrics, kanban_cards, ideas).
- Soft deletes: **not used**. Deletes are real deletes (SRS: room deletion permanently removes content).
- Enums: PostgreSQL enums via Drizzle `pgEnum` (listed below).
- All FKs are explicit with `ON DELETE` behavior chosen deliberately (noted per table).
- Migrations: `pnpm --filter db generate` → review SQL → `pnpm --filter db migrate`. Never edit a committed migration.

### rubrics
id, name, faculty_id FK → users, criteria jsonb `[{name, description, max_points}]`, is_global boolean, assignment_id FK nullable, created_at / updated_at. Default system rubric seeded (5 × 20 pts, SRS §11.2).

### comments
id, post_id FK cascade, author_id FK, parent_comment_id FK (self, nullable — **one level only**, enforced in service: reject if parent already has a parent), body (Markdown), created_at.

### upvotes
id, post_id FK cascade, user_id FK cascade, created_at. `UNIQUE(post_id, user_id)`. Same table pattern for **idea_upvotes** `UNIQUE(idea_id, user_id)`.

### saves
id, post_id FK cascade, user_id FK cascade, created_at. `UNIQUE(post_id, user_id)`.

### follows
id, follower_id FK, following_id FK, created_at. `UNIQUE(follower_id, following_id)`, `CHECK (follower_id <> following_id)`.

### team_members
id, post_id FK cascade, user_id FK, status team_status default `pending`, created_at. `UNIQUE(post_id, user_id)`.

**No FK to posts for room features. No attendance/session tables exist — presence is Redis-only.**

### room_members
id, room_id FK cascade, user_id FK cascade, role room_role default `member`, avatar_sprite int (0–5, chosen on first Live Space entry), last_position jsonb `{x, y, direction}` (written on disconnect only), created_at. `UNIQUE(room_id, user_id)`.

### room_invites
id, room_id FK cascade, invitee_id FK, inviter_id FK, status team_status default `pending`, created_at. Declined invites hidden from other members (FR-ROOM-04).

### room_messages
id, room_id FK cascade, sender_id FK, body text (plain text only, FR-ROOM-35), created_at. Index `(room_id, created_at)`. Deleted only via room deletion cascade (FR-ROOM-36).

### kanban_cards
id, room_id FK cascade, column kanban_column default `todo`, title, description, assignee_id FK → users nullable, move_note text nullable (FR-ROOM-21), position real (fractional ordering), created_at / updated_at.

### kanban_columns
id, room_id FK cascade, key kanban_column, label text — stores **renamed** column labels only (FR-ROOM-18); absence = default label.

### build_journey_entries
id, room_id FK cascade, type text (`room_created`, `blueprint_first_edit`, `stage_change`, `weekly_done_count`), payload jsonb, created_at. Rows are append-only, generated by server-side triggers in the service layer — never user-authored (FR-ROOM-17).

### refresh_tokens
id, user_id FK cascade, token_hash text, expires_at, created_at, revoked_at nullable. Rotation on use.

## 3. Raw SQL Exceptions (the only two)

**`packages/db/src/queries/lineage.ts`** — recursive CTEs for ancestor/descendant traversal with depth (FR-LINEAGE-04). Canonical SQL is in `foundry_srs.md` §8.2.

**`packages/db/src/queries/similarity.ts`** — pgvector cosine similarity scoped to ancestor IDs (SRS §8.3):
```sql
SELECT post_id, 1 - (embedding <=> $1) AS similarity
FROM post_embeddings WHERE post_id = ANY($2)
ORDER BY similarity DESC;
```

Everything else: Drizzle. No exceptions.
